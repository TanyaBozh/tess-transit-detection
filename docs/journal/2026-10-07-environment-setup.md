# 2026-10-07 — Подготовка окружения для eleanor

## Цель

Подготовить воспроизводимое Python-окружение для работы с `eleanor 2.0.5` и зафиксировать возникающие проблемы так, чтобы этот опыт можно было повторить на другом компьютере.

## Исходная проблема

Первоначально `eleanor` запускался в Python 3.11, но импорт завершался ошибкой.

Оказалось, что код `eleanor 2.0.5` использует старый API `photutils`, например импортирует:

- `CircularAperture`
- `RectangularAperture`
- `aperture_photometry`
- `MMMBackground`

непосредственно из `photutils`.

При современной версии `photutils` этот API уже изменён.

Кроме того, код `targetdata.py` импортирует TensorFlow напрямую:

```python
import tensorflow as tf
```

хотя TensorFlow не указан в обычном `requirements.txt` пакета как обязательная зависимость.

## Попытка 1: окружение внутри каталога проекта

Было создано виртуальное окружение `tess-eleanor` внутри рабочего каталога.

Возникли две отдельные проблемы:

1. PowerShell не разрешал запускать `Activate.ps1` из-за политики выполнения скриптов.
2. Установка TensorFlow столкнулась с проблемой Windows path length при установке файлов с очень длинными путями.

Вместо изменения системной политики и включения Windows Long Paths было принято решение создать новое окружение в каталоге с коротким путём.

## Решение

Создано окружение:

```
D:\venvs\tess-eleanor
```

с Python 3.10.11.

Это позволяет использовать окружение напрямую через:

```
D:\venvs\tess-eleanor\Scripts\python.exe
```

без необходимости активировать его через PowerShell.

## Проверки

### NumPy, SciPy и Astropy

Импортированы успешно.

### Photutils

Проверены старые импорты, которые использует `eleanor`:

```python
from photutils import (
    CircularAperture,
    RectangularAperture,
    aperture_photometry,
    MMMBackground
)
```

Импорт работает с `photutils 1.11.0`.

Появляются предупреждения об устаревшем API, но это предупреждения, а не ошибки.

### Lightkurve

Импортирован успешно, версия 2.4.2.

Lightkurve сообщил о переносе каталога cache на новый путь. Это предупреждение не блокирует работу.

### TensorFlow

Импортирован успешно, версия 2.10.1.

При запуске появляется сообщение о невозможности загрузить `cudart64_110.dll`. Это ожидаемо при отсутствии соответствующей CUDA/GPU-среды и не мешает работе TensorFlow в CPU-режиме.

### Eleanor

Проверка:

```python
import eleanor
print(eleanor.__version__)
```

результат:

```
eleanor 2.0.5
```

Таким образом, базовый импорт `eleanor` успешно работает.

## Почему версии зафиксированы

Устанавливать последние версии всех библиотек вслепую было бы неправильно: `eleanor 2.0.5` использует старые интерфейсы некоторых зависимостей.

Текущий `requirements.txt` является первоначальным набором прямых закреплённых версий, проверенных в рабочем окружении. Позже его следует уточнить/расширить для полной воспроизводимости установки, если это потребуется.
